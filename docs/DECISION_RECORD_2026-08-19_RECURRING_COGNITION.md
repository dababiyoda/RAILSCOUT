D1. Over-automation risk: scheduled cadence could generate activity without progress.
- Redesign: anti-stagnation rule requires each useful run to add evidence, update estimate, revise confidence, kill/strengthen/merge, sharpen validation, or log a defect.

D2. Authority drift risk: Agent B could be mistaken for an executor.
- Redesign: Agent B is explicitly a recurring cognition operator with no authority to publish, spend, contact people, or alter governance.

D3. Product overclaim risk: Workspace Agent capability could be overstated.
- Redesign: official OpenAI product facts are preserved as constraints and live execution is not claimed until proven.

D4. Maintenance burden: too many docs can become theater.
- Redesign: initialize only the minimum repository spine: README, protocol, founder ledger, SOP, prompts, ledgers, decision record, egregore connection.

D5. Cross-repo inconsistency: RailScout repo may say active while Kernel still says planned.
- Redesign: RailScout records local connection and marks Kernel registry update as separate unresolved decision.
