# RailScout Metrics

RailScout must measure whether the refinery changes reality, not whether it produces impressive output.

## Primary metric 1 - Validated Business Discovery Throughput

Definition:

> The speed and quality with which RailScout converts raw uncertainty into externally validated commercial knowledge.

This is not idea volume.

Signal chain:

```text
Raw signal -> evidence -> hypothesis -> validation test -> external result -> decision -> reusable asset or kill record
```

Healthy movement:

- faster time from signal to test;
- clearer evidence classifications;
- cheaper falsification;
- stronger external signal quality;
- fewer repeated mistakes;
- better next actions.

Unhealthy movement:

- more documents without external evidence;
- more ideas without ranking;
- more strategy without tests;
- more research without decision quality;
- more automation without authority clarity.

## Primary metric 2 - Profitable Validated Business Discovery Assets

Definition:

> Validated discoveries that become reusable, revenue-generating assets, paid pilots, repeatable offers, launch packets, or ventures.

Examples:

- paid diagnostic;
- signed pilot;
- repeatable proof packet;
- reusable customer interview system;
- launch-ready venture packet;
- reusable market architecture primitive;
- validated wedge with budget owner and external evidence.

## Supporting metrics

### Signal metrics

- raw signals captured per week;
- percentage classified by evidence tier;
- percentage rejected as noise;
- source quality distribution.

### Evidence metrics

- claims with primary evidence;
- claims with contradictory evidence;
- claims still assumption-only;
- time to resolve key unknowns.

### Validation metrics

- time from signal to test;
- cost per falsified hypothesis;
- tests completed per week;
- external signal rate;
- paid-validation rate;
- data-access rate;
- signed-pilot rate;
- repeat-use rate.

### Commercial metrics

- revenue from validated assets;
- value created per founder hour;
- time from validation to revenue;
- average contract/pilot value;
- customer acquisition source;
- retained/repeated use.

### System metrics

- reusable asset conversion rate;
- decision-reversal rate;
- repeated-error rate;
- number of killed opportunities with preserved lessons;
- SOP improvements created from failures;
- unreviewed assumptions older than threshold.

## External signal quality ladder

Do not treat weak signal as strong validation.

1. No response.
2. Rejection.
3. Objection.
4. Information supplied.
5. Introduction.
6. Meeting booked.
7. Workflow data access.
8. Pilot interest.
9. Signed pilot.
10. Payment.
11. Repeat use.
12. Institutional reliance.

RailScout must record the actual signal level, not the desired interpretation.

## Vanity metrics to reject

RailScout should not treat these as success by themselves:

- number of ideas;
- number of pages written;
- number of AI outputs;
- length of doctrine;
- subjective excitement;
- internal confidence;
- unverified market size;
- non-buyer praise;
- social attention without conversion;
- weak yeses without next commitment.

## Single Bottleneck Metric

Every operating cycle should identify the current Single Bottleneck Metric.

Examples:

- completed buyer interviews;
- verified problem-cost records;
- access to workflow data;
- signed pilot agreements;
- paid diagnostic conversions;
- repeat usage;
- validated proof-packet acceptance;
- time from raw signal to external test.

The Single Bottleneck Metric must answer:

> What one measurable constraint is presently limiting progress toward the next stage gate?

## Splash-radius rule

Each major action should identify what else it moves.

Example:

Action: run five buyer interviews with budget owners.

Direct metric moved:

- completed buyer interviews.

Splash radius:

- budget clarity;
- pain severity;
- wording for offer;
- objection map;
- willingness to pay;
- stakeholder map;
- validation sprint design.

## Reporting standard

A RailScout operating report should show:

- active objective;
- Single Bottleneck Metric;
- current evidence tier;
- strongest counterexample;
- action taken;
- external result;
- confidence update;
- system improvement;
- exactly one next action.
